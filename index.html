设计要点（本次原型固化）

  • 拒单零代价：不降权、不扣分、不影响可见性；未响应 ≠ 接受（防强制派单）
  • 到岗确认仅「确认」级：记录履约证据，不考核、不惩罚、不以签到为标的
  • 结算＝报酬明细清单（对齐新规征求意见稿第十三条）
  • 工作记录可一键下载（对齐第二十三条台账要求）
  • 双端：小程序优先；

门店端要点

  • 发单：从「任务卡库」选卡发布，任务实时进入 C 端广场（演示）
  • 验收：店长确认 ＋ AI 初判辅助；退回返工不扣款
  • 合规视图：红线动作开关全部不可启用（系统层做不到）——「强制派单/请假审批/考勤打卡/惩罚扣款」

承接方工作台（示例：××盘点服务有限公司）— 对公承揽

A/S 端要点（🟢 轨 · 优先对公司）

  • 项目包「成包不成点」：接单方是公司/团队；平台不向承接方人员派单、排班、考核（假外包真派遣红线——相关功能不存在）
  • 履约自主：承接方用自有组织与工具完成，按成果验收（示例：盘点差异率 ≤ 1%）
  • 对公结算与开票，写入同一条证据链（可与 C 端流程对照）

为什么这是产品功能，不是法务补丁

  • 协议流 / 履约流 / 资金流 / 票据流：事中生成、同一时间轴、可导出为争议证据包
  • 「自愿性证据」：接受与拒绝都留痕 → 回应 CCFA「无真实派单接单场景」的点名
  • 记录只追加、不可修改、不可删除（审计留痕）
平台运营控制台（我方自身视角 · 示例数据）

平台视角要点

  • 三层隔离 ＋ 铁律「合同主体＝用工主体＝发薪主体」在模型层强制
  • 规则＝可版本化配置（每条规则带回归用例）；参数卡按辖区＋时点，过期自动告警
  • 红线不是「开关关掉」，是不存在启用状态（含拦截日志）
  • 计费锚点 6.8–7%；不以结算速度收费（YoungOnes 先例）

这是「严格甄别」工具

  • 九维体检：三区校验 → 黑名单扫描 → 判例要素勾稽 → 四流完整性 → 法规对照 → 依赖度提示 → 举证预检 → 参数时效 → 结论
  • 先在 ① 或 ③ 完整走一遍流程，本页才有体检对象
  • 判例要素对照为设计自检（演示口径），不是个案法律意见
  • 待律师复核项会一并列出（并入 Q7 复核包）
